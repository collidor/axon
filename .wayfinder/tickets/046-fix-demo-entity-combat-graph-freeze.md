# Ticket 046: Fix Demo Entity Combat Pipeline Graph Freeze & Microtask Loop

## Context & Problem
When selecting the "Entity Combat Pipeline" graph preset (`combat-engine` in `demo/src/presets.ts`) in the Axon Studio demo, the application froze completely, locking up the browser thread.

### Root Cause Analysis
1. **Destructive DOM re-renders in `AxonCompareNode`**:
   - `AxonCompareNode` in `src/web-components/nodes/dataGraphNodes.component.ts` unconditionally replaced `this.innerHTML = ...` on every `render()`.
   - In `combat-engine`, values propagated from `dmg-calc:result` to `gate-node:a` (an `AxonCompareNode`).
   - Receiving an input called `AxonBaseNodeElement.onInputUpdate()`, which triggered `this.render()`.
   - Replacing `this.innerHTML` destroyed `<axon-port-in id="gate-node:a">` and `<axon-port-out id="gate-node:result">` and recreated them.
   - Newly mounted `<axon-port-in>` elements fired `connectedCallback()`, dispatching the `axon-port-registered` custom event.
   - In `AxonGraph`, `axon-port-registered` scheduled `rebuildAdjacency()` in a microtask (`queueMicrotask`).
   - `rebuildAdjacency()` pushed port values via `setPortValue()`, re-triggering `onInputUpdate` -> `render()` -> port destruction -> `axon-port-registered` -> unbounded microtask recursion loop.
2. **Defensive Guard Missing in `BaseGraph.settle()`**:
   - `settle()` in `src/core/base.graph.ts` contained a `while (this.#pendingNodes.size > 0)` loop without an iteration cap, causing deadlocks if any cycle or re-triggering occurred.
3. **Overly Aggressive Base Node Re-rendering**:
   - `AxonBaseNodeElement.onInputUpdate` and `onOutputUpdate` defaulted to calling `this.render()`, causing nodes without custom display needs to re-render DOM during standard graph execution.
4. **Sibling Nodes Lacking Incremental DOM Guards**:
   - `AxonGateNode` and `AxonTypeConvertNode` also wiped `this.innerHTML` unconditionally instead of updating existing DOM cards.

## Changes Made
1. **Incremental DOM Updates in `AxonCompareNode`, `AxonGateNode`, and `AxonTypeConvertNode`**:
   - Refactored `render()` in all three components to check for existing DOM cards (`.compare-node-card`, `.gate-node-card`, `.convert-node-card`).
   - Isolated dynamic inputs/buttons into discrete slots (`.compare-b-slot`, `.gate-open-slot`, `.convert-fallback-slot`), ensuring `<axon-port-in>` and `<axon-port-out>` custom elements are never destroyed or re-registered during updates.
2. **Default No-Op Value Hooks in `AxonBaseNodeElement`**:
   - Changed `AxonBaseNodeElement.onInputUpdate` and `onOutputUpdate` to no-ops by default.
   - Overrode `onInputUpdate` specifically in `AxonDisplayNode` where live output display is needed.
3. **Port Registration Guard in `AxonGraph`**:
   - Added a guard in `axon-port-registered` listener: if the port is already connected in `#connectedPorts`, redundant adjacency rebuilds are skipped.
4. **Safety Cap in `BaseGraph.settle()`**:
   - Added `maxIterations = 100` iteration limit to `settle()` matching `flush()`, preventing unbounded recursion loops.
5. **Interactive Run Support in Demo**:
   - Updated `StudioView.vue` `runCompiledCode()` to support `executeCompiledGraph()` generated by `@collidor/axon` graph compiler.
6. **Regression Test Suite**:
   - Created `src/web-components/__tests__/combatEnginePreset.spec.ts` asserting that importing `combat-engine` into `AxonStudio` loads immediately without freezing, stabilizes all ports, calculates expected combat values, and compiles cleanly to zero-dependency TypeScript.
